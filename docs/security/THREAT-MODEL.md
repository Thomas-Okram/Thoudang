# Thoudang — Threat model (STRIDE-lite)

Scope: the hackathon prototype as built (Express API + SQLite + React SPA on one laptop, LAN /
phone-hotspot access, one outbound call per image to the Claude API). Synthetic SPECIMEN data only.
This is a design aid, not a certification. Last reviewed: 8 Oct 2026.

## What we protect

| Asset                              | Where it lives                                                                                                                      | Why it matters                                                           |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Aadhaar number                     | Only in the uploaded card/form **images** and, for milliseconds, in Claude's reply. Stored as last 4 digits + `checksumValid` only. | Statutory restrictions on storing/displaying it (see DATA-PROTECTION.md) |
| Applicant documents (images)       | `apps/api/uploads/<caseId>/` (GPS-stripped originals + processed JPEG)                                                              | Identity, address, bank details of elderly / IDP applicants              |
| Extracted fields, flags, decisions | SQLite `data/thoudang.db`                                                                                                           | Drive eligibility; officers act on them                                  |
| Audit trail                        | `audit_log` (+ `audit_chain`, anchor file)                                                                                          | Accountability for every AI read and officer decision                    |
| Officer identity / authority       | Signed session cookie; PINs in env                                                                                                  | Only a DSWO may approve                                                  |

## Trust boundaries & data flow

```
 Phone (LAN) ──┐                                    ┌──> Claude API (outside India, TLS)
 Officer PC ───┼─> [security layer] ─> Express API ─┤      images + prompts, masked on return
 Citizen (QR) ─┘   headers/CSP, origin   │          └──> Gemini TTS (Manipuri notice text: name,
                   lock, limits, auth,   │                reference, deficiencies; Aadhaar redacted)
                   upload guard          v
                                  SQLite + uploads/ (laptop disk)
```

## STRIDE

|                            | Threat                                                                                                          | Mitigation in this build                                                                                                                                                                                                                                                                                             | Residual risk / next step                                                                                                                                                         |
| -------------------------- | --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **S**poofing               | Anyone on the LAN acts as the DSWO by choosing them in the dropdown / sending `X-Officer-Id`                    | PIN sign-in → HMAC-signed, httpOnly, `SameSite=Strict` session cookie (`security/session.ts`). In `AUTH_MODE=session` (default) a client-sent `X-Officer-Id` is discarded; the cookie identity always wins. PINs held only as scrypt hashes in memory; 5 wrong PINs → 5-min lock-out; login rate-limited per client. | 4-digit PINs are weak; demo PINs are public. Production: SSO / e-Pramaan or Parichay + MFA, per-user PINs set by the officer. `AUTH_MODE=header` exists only as a stage fallback. |
|                            | Forged status link enumerates citizens                                                                          | Status links carry `HMAC(ref)`; unknown ref and bad token return the same 404 (existing).                                                                                                                                                                                                                            | Set `STATUS_LINK_SECRET`.                                                                                                                                                         |
| **T**ampering              | Edit/delete an audit entry to hide an approval                                                                  | `audit_log` UPDATE/DELETE blocked by triggers; **hash chain** (HMAC-SHA256 over previous hash + row) in `audit_chain`, also append-only; head written to an anchor file; `npm run audit:verify` exits 1 on any edit, deletion, insertion or chain wipe.                                                              | An attacker with disk access AND the `AUDIT_CHAIN_KEY` can rebuild the chain. Ship heads to an external WORM/syslog store; keep the key in a secrets store.                       |
|                            | Malicious upload (polyglot, script named `.jpg`, zip bomb, path traversal)                                      | Magic-byte allow-list (JPEG/PNG/WebP/HEIC; ZIP on batch only, every entry checked); size/count/field limits; zip entry and unpacked-size caps; random server-side file names; extension corrected to real content; images are decoded/re-encoded by sharp before any use.                                            | HEIC parsing relies on libheif (keep sharp patched).                                                                                                                              |
|                            | Cross-site request makes the officer's browser approve a case (CSRF)                                            | `SameSite=Strict` cookie + origin policy: POST/PATCH/DELETE from a non-allowed `Origin` → 403.                                                                                                                                                                                                                       | —                                                                                                                                                                                 |
| **R**epudiation            | "I never approved that"                                                                                         | Every AI extraction, rule result and officer action is audited with actor, time, before/after and reason; actor comes from the authenticated session; chain makes later edits detectable. Sign-in/out and refused uploads go to the JSON log.                                                                        | Add login events to the audit table (needs an enum change — see REPORT-security.md).                                                                                              |
| **I**nformation disclosure | Full Aadhaar number stored, logged or shown                                                                     | Masked in `normaliseExtraction` before cache/DB/log/SSE/API; logger redacts 12-digit runs; images served only redacted from the server; originals never served; leak scanner + tests prove 0 findings (incl. raw DB file).                                                                                           | **The original image (with the full number) is sent to the Claude API** for reading — see DATA-PROTECTION.md §4.                                                                  |
|                            | Location of the applicant's home leaks via photo EXIF GPS                                                       | GPS IFD and XMP `exif:GPS*` values stripped in place from every stored copy at the upload door (lossless; orientation kept).                                                                                                                                                                                         | —                                                                                                                                                                                 |
|                            | XSS steals data / session                                                                                       | Strict CSP: `script-src 'self'`, no inline script, `object-src 'none'`, `frame-ancestors 'none'`; cookie is httpOnly; React escapes output. `style-src-attr 'unsafe-inline'` is the one concession (style attributes only).                                                                                          | —                                                                                                                                                                                 |
|                            | Cross-origin reads from another site                                                                            | CORS only for same-origin, localhost and private-LAN IPs on our ports (+ `CORS_ORIGINS`).                                                                                                                                                                                                                            | —                                                                                                                                                                                 |
|                            | Someone on the LAN reads case data / redacted images, uploads packets or triggers demo reset without signing in | `REQUIRE_SIGN_IN=1` makes every `/api` route need a session except health/meta, sign-in, the citizen status page and the phone QR upload flow (its session id is an unguessable capability URL).                                                                                                                     | **Off by default** for the 9 Oct demo — the web app does not yet redirect to `/api/auth/login` on 401. Turn on once it does.                                                      |
|                            | Images kept forever                                                                                             | Retention job deletes images `RETENTION_DAYS` (default 30) after approval; keeps masked data + audit; audited (`IMAGES_PURGED`).                                                                                                                                                                                     | Cases sent for correction and never closed are not purged yet (policy decision needed).                                                                                           |
|                            | Laptop stolen                                                                                                   | —                                                                                                                                                                                                                                                                                                                    | Use full-disk encryption (FileVault/BitLocker) on the demo machine; SQLite is not encrypted at rest.                                                                              |
| **D**enial of service      | Upload flood fills the disk / stalls Claude quota                                                               | Upload rate limit (120/min default), body-size limits before parsing, per-file 20 MB, batch 600 MB, zip caps; Claude calls already bounded by `p-limit`, timeouts and retries.                                                                                                                                       | In-memory limiter is per process; behind the Vite dev proxy all clients share one bucket.                                                                                         |
| **E**levation of privilege | Dealing Assistant approves                                                                                      | Permission checks on the API (`officers.ts`) unchanged; identity now authenticated, so the role cannot be self-asserted.                                                                                                                                                                                             | —                                                                                                                                                                                 |

## Assumptions

- Single trusted host; the LAN is semi-trusted (office Wi-Fi or the presenter's hotspot).
- Plain HTTP on the LAN (no certificates at the venue). Hence no HSTS and no
  `upgrade-insecure-requests`; cookies get `Secure` automatically when served over HTTPS.
- Demo PINs and default keys are public by design; every one has an env override.
